## Notes

Done in full, no split. What the story built:

- Types library: `extension-points.ts` (entries, `EXPORT_NAMES` with `Header`, `DATA_ENTRIES`, areas, `BcPageParts`, `BcManifest`) and `event-protocol.ts` (events, actions, error codes, `BcUserTask`, `BcWorkflow`, `BcElementProps`).
- Module kit: ported from the VanillaBP kit 0.1.0-snapshot.6 as TypeScript, compared by name (`kit.test.mjs` lists its exports). `bc-check-entries` reads its data entries from `EXPORT_NAMES`.
- Module host: registry, one loader, ask/load/draw, name checks, manifest recheck, new-build handling, `isDefined` (added so the page can skip the loading state).
- Page of a user task (`TaskPage.vue`, `src/modules`): states task/ask/load, one note per failure, areas body/information/actions or all, barrier of a suspended task (`AreaFrame.vue`), header look of the open task, title link (EXTERNAL opens a tab), mark read on open, BroadcastChannel answer of the list pages.
- Test modules in `e2e/modules` (React, Vue and Angular with the Angular CLI), served by the simulator below `/wm/<id>/`; fake modules (plain JavaScript, made by a test) for the failure cases.
- Changed existing test: `tests/workspaces.test.mjs` PKG-045 now expects the workspace `e2e/modules/*` after `e2e/compare`, because the test modules are workspaces of the one lock file.
- The update stream does not exist yet. TF-044 reads the task again when the browser tab comes back to the front (`visibilitychange`), the same read the stream will trigger later. The test dispatches that event.
- The area frames of the page are drawn for the page of a case too later; the case page and the header actions (claim, barrier of the hard claim) come in later stories.
- Conformance modules of the VanillaBP kit are not part of the repository yet; PKG-040 runs over the three test modules and a failing fixture.
